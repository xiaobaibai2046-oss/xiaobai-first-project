# 知序 · 南京初中学习空间

静态学习应用，独立于原旅行网站。无需安装第三方运行依赖，无需账号或密钥。九科包括语文、数学、英语、物理、化学、生物、历史、地理和道德与法治。

## 运行

在 `/workspace/xiaobai-first-project` 运行：

```bash
python3 -m http.server 8010 --bind 0.0.0.0
```

通过该 HTTP 服务的 `/jiangsu-study/` 路径使用应用。浏览器需要以 HTTP 加载 ES 模块，不能直接通过 file 协议打开。原网站保留在根路径。本应用无需运行原网站的构建脚本。

## 功能

- 知识点：九科各 100 个，按学科、建议年级、知识主题、关键词和有来源的版别组合筛选；搜索也覆盖已有例子与提醒。每页 36 个，明确显示筛选总数、当前范围和页数。
- 内容类型：原有 129 个带例子、提醒及原创练习；新增 771 张原创讲解卡含具体概念、规则、条件或常见区别，附开放式复述自查，不假装已有客观题。
- 数量清单：首页逐科展示知识点、配题、教材关联和主题数，统计从实际数据计算。
- 教材：按人教、苏科、苏教和年级、学科筛选目录，逐章打开对应入门知识点，查看旧版/修订信息与公开镜像来源。
- 学习：标记学完、单题或连续练习、解析、自动错题本和进度记录。学完仅表示阅读，不自动代表掌握。
- 真题资料：五年窗口按 2026-10-29 确定为 2022—2026；支持用户结构化资料导入、知识点关联、单选批改、主观题参考对照、独立待巩固列表、导出和恢复备份。
- 数据：只保存在本机浏览器，不上传、不跨设备同步。存储不可用时提示，并允许本次页面内继续使用。不同页面来源/端口的浏览器记录不自动共享。

通用模式年级是建议；选择具体版别后，知识点的年级筛选依据该镜像的教材册次，例如反比例函数在这里的苏科版目录属于八年级下册、人教版目录属于九年级下册，不能把统一推荐年级机械套给两版。

## 资料来源与核验边界

教材公开镜像：[TapXWorld/ChinaTextbook](https://github.com/TapXWorld/ChinaTextbook)。读取实际 PDF 的目录文字；对扫描页使用中文 OCR，并对苏科目录及部分版权页作图像复核。苏科七下源文件分为两片，按 `.1`、`.2` 顺序合并为 PDF 后读取。产品只保存章节标题、自己撰写的基础讲解及来源元数据，不随产品分发整本教材 PDF。

[textbook-catalog.js](./textbook-catalog.js) 记录各册固定 Git 提交、路径、PDF 文件 SHA-256、目录页和关联内容。能确认的版次据版权页记录，不能确认的标记“旧版镜像，具体版次未确认”。目录关联采用 `source-read` / `mirror-linked` 状态，**不冒称出版社官方认证或南京现行教材确认**。每章的 `coverage` 为 `core-introduction-only`。

其他尝试及排除依据见 [source-investigation.json](./source-investigation.json)：

- 官方教材、教育资源和南京考试站点的当前 HTTPS 请求仍返回网络代理 403。
- 一个“南京中考”项目实际是无逐题原卷出处的知识练习，且存在答案问题，未作为真题来源。
- 一份文件名写“2010—2026”的公开试卷汇编，原生 Git 克隆成功后，已读到的题目文档明确标注**安徽**，不移作南京真题；原生 Git LFS 取 PDF 另报 `Resource not accessible by integration`。
- 另一个公开索引中的南京卷为 **2018 年**，超出五年窗口，没有混入。
- 网盘介绍、截图或题库项目名称，不足以支持原题身份、年份和答案核验。

继续在线收录所需的 10 个具体域名已保存到环境配置草稿（官方入口、教育资源网站和 GitHub 大文件下载域名）。这只是已保存的草稿，不代表当前网络已放行或已发布。需在环境设置中查看并保存，随后发布环境；取得新机器访问结果后再继续核验原卷。Git LFS 的集成访问拒绝与域名网络限制是不同问题，不保证网络设置能解决 LFS 权限。

后续应补齐各科实际用书的版权页、修订版目录及南京五年原卷/答案/评分说明；地理、生物等考试安排、考试年级与卷别依据原件分别核对，不预设九科每年均有统一中考卷。

## 试题资料导入与备份

“五年中考资料”中可导入 UTF-8 JSON，格式见 [exam-pack.schema.json](./exam-pack.schema.json)，知识点 ID 见 [knowledge-index.json](./knowledge-index.json)。Schema 是格式说明，不是可以直接导入的试卷。

资料包顶层为 `{"schemaVersion":1,"questions":[...]}`。每题必填：`year`（2022—2026 整数）、`city`（南京）、`subject`（知识点索引中的学科代码）、`questionNumber`、`type`、`prompt`、`source.title`、`source.locator`、`explanation`。可通过 `lessonIds` 关联知识点。可省略 `source.url`，填写时须为无账号密码的 HTTPS 地址；来源名称可写文件名，定位可写原卷页码与题号。

- `single-choice`：2—8 个纯文字 `options`，以及从 0 开始的答案序号 `answer`，依资料答案自动批改。
- `written`：需有 `reference`，只展开对照和手动标记待巩固，不自动计分或计入正确率。
- 每批最多 500 题、2 MB，本机最多 2000 题。以年份、学科、题号区分题目，不同卷别应写入题号；相同内容去重，冲突拒绝覆盖，整批校验通过后才加入。
- 用户导入始终标记“用户资料 · 未核验”，导入文件自称 verified 不会提高核验状态。正式原题须另经来源审核。
- 应用不做 OCR，也不直接解析 PDF、图片或 Word；本轮研究使用的 OCR 工具在开发环境运行，不随应用提供。可通过对话提供原件，由后续整理任务处理。
- 导出备份包括导入资料及最近 1000 次资料答题；恢复合并去重，不覆盖冲突题，待巩固状态取并集。
